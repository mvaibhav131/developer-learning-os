Almost every interview has the question "Tell me about a project you worked on." Your answer shows what you really built, how you think and how clearly you communicate. Many candidates describe only the technology: "I used React, Node.js and MongoDB." A stronger answer explains the **problem**, **your part** and the **result**. This lesson gives you a simple structure that works for college projects and real jobs.

> **Hinglish mein:** Project batate waqt sirf tools ki list mat bolo. Pehle problem batao, phir tumne kya kiya, kaunsi mushkil aayi, aur result kya mila. "I" jahan tumne kaam kiya, "we" jahan team ne.

## The six-part structure

| Part | Question it answers | Starter phrase |
| --- | --- | --- |
| 1. Context | What is it and why does it exist? | It's a web app that helps... |
| 2. Role | What did you do? | I was responsible for... |
| 3. Tech | What did you use, and why? | We used Node.js because... |
| 4. Challenge | What was the hardest problem? | The main challenge was... |
| 5. Result | What changed? | As a result, ... |
| 6. Learning | What did you learn or what would you improve? | If I did it again, I would... |

## Sample answer

> It's a library management web app for our college. Students can search for books and reserve them online. I built the backend with Node.js and PostgreSQL, and I designed the database and the REST API. The main challenge was that two students could reserve the same book at the same time. I solved it by using a database transaction with a lock. As a result, we had no duplicate reservations during the pilot, and about two hundred students used it in the first month. If I did it again, I would add automated tests earlier.

Use your own real facts. Do not invent numbers.

## I or we?

- Use **I** for what you personally did: "I designed the schema."
- Use **we** for team decisions: "We decided to use PostgreSQL."
- Never take credit for team work, and never hide your own work behind "we".

## Strong verbs

| Instead of | Use |
| --- | --- |
| did | designed, built, implemented, developed |
| made faster | optimised, reduced, improved |
| moved | migrated, refactored |
| helped | collaborated, supported, led |
| solved | debugged, fixed, resolved |

## Tenses

Use the **past simple** for what you did: "I built the API." Use the **present simple** for what the system does: "The app sends an email when a book is available."

## Phrases to use

```phrases
It's a web application that helps students reserve books online.
I was responsible for the backend and the database design.
We chose PostgreSQL because we needed transactions.
The main challenge was handling two reservations at the same time.
I solved it by using a database transaction with a lock.
If I did it again, I would write the tests earlier.
```

## Follow-up questions

| Question | How to answer |
| --- | --- |
| Why did you choose this technology? | Give one reason and one trade-off: "We chose X because..., although it..." |
| What was the hardest part? | Describe one concrete problem and your solution. |
| What would you improve? | Be honest: "I would add tests / monitoring / caching." |
| What was your role in the team? | Name your tasks and who you worked with. |

## Practice

1. Choose two projects: one main and one backup.
2. Fill in the six parts for each. Write one or two sentences per part.
3. Say each one aloud in 90 seconds. Record and listen.
4. Prepare answers to the four follow-up questions.

## Recap

- Context, role, tech, challenge, result, learning.
- I for your work, we for the team.
- Use strong verbs and real facts.
- Prepare two projects and practise the follow-up questions.
