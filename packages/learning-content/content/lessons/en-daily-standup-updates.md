A daily stand-up is a short team meeting, usually 10 to 15 minutes. Each person speaks for about a minute. For many people it is the most stressful minute of the day, but it is also the easiest to prepare, because the structure is always the same: **yesterday, today, blockers.**

> **Hinglish mein:** Stand-up mein teen cheezein batani hoti hain: kal kya kiya, aaj kya karoge, aur kahin kuch atka hua hai ya nahi. Pehle se 3 chhote sentences taiyaar rakho, aur bol do.

## The three-part structure

| Part | Tense | Example |
| --- | --- | --- |
| **Yesterday** | past simple | I finished the login API and opened a pull request. |
| **Today** | present continuous or going to | I'm working on the payment tests. I'm going to deploy to staging. |
| **Blockers** | present simple or present continuous | I'm blocked on the API key. I need a review from Rahul. |

Keep each part to **one or two sentences**. If somebody needs more, they will ask you after the meeting.

## A complete update

> Good morning, everyone. Yesterday I finished the login API and opened a pull request. Today I'm working on the payment tests, and I'm going to deploy to staging in the afternoon. I have one blocker: I'm waiting for the API key from the client. That's all from my side. Thanks.

Total: about 45 seconds.

## Useful phrases

```phrases
Good morning, everyone. Here is my update.
Yesterday I finished the login feature and opened a pull request.
Today I'm working on the payment API tests.
I'm going to deploy the fix to staging this afternoon.
I'm blocked on the API key from the client.
I need a code review from Priya on pull request four eighty-two.
I should be done by Thursday.
No blockers from my side. Thanks.
```

## Words you will use

| Word | Meaning |
| --- | --- |
| ticket | a task in your tracker |
| pull request (PR) | a request to merge your code |
| merge | add code into the main branch |
| deploy | release code to an environment |
| staging | the test environment before production |
| blocker | something that stops your work |
| dependency | something you need from another person or team |
| ETA | estimated time of arrival: when you expect to finish |

## Common mistakes

| Wrong | Correct |
| --- | --- |
| Yesterday I am working on the API. | Yesterday I worked on the API. |
| Today I will do work on testing. | Today I'm working on testing. |
| I have no any blockers. | I have no blockers. |
| I am having a blocker. | I have a blocker. |
| I will complete it by tomorrow. | I should finish it by tomorrow. |

## Tips

1. Write three bullet points before the meeting: yesterday, today, blocker.
2. Name the **ticket or feature**, not the whole story.
3. Give a **time**: "by Thursday", "this afternoon". It helps the team plan.
4. For a blocker, say **what you need and from whom**: "I need a review from Priya."
5. If you do not have a blocker, say so clearly. Do not stay silent.

## Practice

1. Write your own three-part update using the structure above. Keep it under 80 words.
2. Say it aloud and record it. It should be about 45 to 60 seconds.
3. Listen. Did you use the past simple for yesterday? Did you name a blocker or say "no blockers"?
4. Repeat tomorrow with your real update.

## Recap

- Yesterday (past simple), today (present continuous or going to), blockers.
- One or two sentences for each part. Name the ticket and give a time.
- For a blocker, say what you need and from whom.
- Prepare three bullets. A prepared minute is easier than an improvised one.
